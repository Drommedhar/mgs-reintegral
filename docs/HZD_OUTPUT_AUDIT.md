# Hazard output buffer audit

The selected native sources contain six callers of `HZD_GetNearVector`. One still supplied only one `SVECTOR`: Liquid's ledge-climb action, `liquid_800CBB50`. It now allocates two and continues to use the first result for movement.

The helper writes `vx`, `vy`, and `vz` of **both** vectors, even when the preceding query reports one nearby hazard. A single eight-byte destination therefore permits writes beyond the object at offsets 8, 10, and 12. Neither vector's padding is written. See [the helper](../vendor/mgs/source/libhzd/near.c) and [the corrected climb action](../vendor/mgs/source/animal/liquid/liquid_action.c).

## Original instruction evidence

The retail Disc 2 `s18a/4b9b.b` climb routine occupies `800CBB50..800CBF38` (250 instruction words, SHA256 `f7659732153559f0f2d1914d0f98c971be5b73d30d8c44ab181e5535ac0f561e`). The private resident-plus-overlay analysis image was checked byte for byte against that overlay range.

- `800CBB50` reserves a `0x40`-byte stack frame. The first saved register is at `sp+0x28`.
- `800CBCB0` calls resident `HZD_GetNearVector` at `80029324`; its delay slot supplies `sp+0x18`. Thus the original has 16 bytes available before the saved registers.
- The resident reader writes halfwords at destination offsets `0, 2, 4, 8, 10, 12`. The original caller then reads only the first vector at `sp+0x18..0x1C`.

The native repair restores that two-vector allocation. It does not change the hazard radius, flags, animation, movement arithmetic, or action transitions.

## Regression evidence

[mgs_liquid_climb_test.c](../tests/mgs_liquid_climb_test.c) extracts and runs the actual climb routine and hazard reader through [prepare_liquid_climb_test.py](../tests/prepare_liquid_climb_test.py). It compares the complete 2,636-byte actor and ordered engine-boundary traces with 840 independently executed original-MIPS cases generated by [reference_liquid_climb.py](../tests/reference_liquid_climb.py):

- Eight authored climb types plus both out-of-range switch cases, 14 timer boundaries from `-1` through `100`, and animation completion on/off.
- Three signed coordinate sets, including 16-bit wraparound; successful queries returning either one or two nearby hazards.
- Actual two-vector helper execution on both sides. A separate guarded-buffer check verifies both outputs, untouched padding, and adjacent canaries.

The test checks the caller's compiler-known destination capacity before invoking the reader. Reverting only the allocation to the recovered single-vector version fails deterministically with `HZD_GetNearVector requires two vectors; caller provides 8 bytes` (exit 1), before an out-of-bounds write. The corrected version passes all 840 cases under strict Win32 compilation.

Climb classification, hazard discovery, animation setup, and sound are observable test boundaries; their internal implementations are not replaced in the game. The zero-hazard error path is not covered: the original routine logs an error and consumes its prior stack contents in that path. This change does not introduce a substitute position or alter that pre-existing error behavior. Runtime coverage remains separate from these instruction comparisons.
