# Domain docs

This repo uses a single-context layout: `GLOSSARY.md` at the repo root and decisions under `docs/adr/`.

## Before exploring

Read `GLOSSARY.md` and ADRs relevant to the area being explored.

If either is absent, proceed silently. The domain-modeling skill creates documentation when terms or decisions are resolved.

## Vocabulary

Use glossary terms in issue titles, proposals, hypotheses and test names. For a missing concept, check existing project terminology first; record an actual gap for domain-modeling.

## Decision conflicts

If a proposal contradicts an ADR, identify the ADR and explain why the decision should be reopened.
